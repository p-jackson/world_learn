# Geometry asset pipeline

Type: research
Status: resolved

## Question

Define how per-entity map geometry gets from Natural Earth into the app as
renderable SVG.

- **Simplification level**: 110m vs 50m for a phone-sized regional-zoom map — pick one, with the size/quality tradeoff.
- **Build-time generation**: the recommended pipeline to turn Natural Earth
  admin-0 (TopoJSON/GeoJSON) into, per entity: an SVG `<path>` `d` string and a
  bounding box (for the regional-zoom `viewBox`). Which projection? Which Rust
  crates (`topojson`, `geojson`, `geo`) or JS step? Static generated asset vs
  runtime conversion.
- **Palestine patch**: Natural Earth folds Palestine into Israel at admin-0 —
  how to add it as a distinct feature.
- **Entity id + display-name field**: which dataset field is the id, which is
  the human-readable name.

Output: the concrete recommended pipeline the spec will name.

## Context

Prior charting research already established feasibility and the dataset choice
— DO NOT redo that. Start from these findings and go deeper on the *pipeline*:

- iOS renders via WKWebView; inline SVG in RSX works like web. ~250 paths is well within budget. Vary the `fill` attribute, not SVG child nodes (Dioxus issue #2274).
- Dataset = Natural Earth **Admin 0 – Countries** (public domain), via `topojson/world-atlas` (`countries-110m.json` / `50m`), or `martynafford/natural-earth-geojson`. Includes Taiwan, Kosovo, Western Sahara, Northern Cyprus, Somaliland, Greenland as distinct features.
- Recommended: precompute paths + bboxes at build time (Rust `topojson`/`geo` + a projection) into a static asset; runtime d3-geo/JS is the fallback.

## Answer

**Decision: 50m base geometry, equirectangular projection, build-time
static asset keyed by `ADM0_A3`, Palestine from the NE point-of-view file.**

- **Simplification: 50m** (not 110m). We zoom *in*, so coastline detail matters;
  110m looks jagged/blocky magnified and drops small nations. Round coordinates
  at build time (~1 decimal projected px) to shrink the shipped asset (well
  under budget after extracting only the ~250 rendered features). 10m is overkill.
- **Projection: equirectangular (Plate Carrée)** with a per-entity
  `cos(lat_center)` horizontal correction. Lon/lat map linearly → bounding boxes
  are trivial and zoom is a pure `viewBox` swap, no per-card re-projection. The
  cos-scale (using the entity bbox's latitude midpoint) removes the high-latitude
  horizontal stretch; because each card shows a small latitude band, one factor
  per entity looks locally correct. Mercator's conformality is worthless here and
  its vertical exaggeration actively hurts.
- **Pipeline: build-time static asset, generated by a small d3-geo Node script**
  (dev-only, never ships): fetch NE 50m → `topojson.feature` →
  `d3.geoBounds`/`d3.geoPath(geoEquirectangular)` per feature → emit JSON (or a
  generated `.rs`) `ADM0_A3 → { name, d, bbox:[minx,miny,maxx,maxy] }`. App loads
  via `include_str!` + `serde_json`, renders all ~250 `<path>` once, varies
  `fill` per card (Dioxus #2274 workaround), sets `viewBox` = target bbox × 3–4.
  All-Rust fallback: `topojson` + `geo` + `geo-svg` + hand-rolled equirectangular
  affine. **Antimeridian caveat**: Russia/Fiji/Alaska cross ±180° — d3-geo cuts
  them correctly; a naive min/max-lon bbox will wrap the globe, so verify those few.
- **Palestine**: source from Natural Earth's **`ps` point-of-view admin-0 file**
  (`ne_10m_admin_0_countries_ps`) — it has a clean Palestine polygon *and* an
  Israel drawn without it, so swap both in over the default merged Israel; no
  boolean geometry. Fallback: union West Bank + Gaza from the disputed-areas layer.
- **Ids/names**: key on **`ADM0_A3`** (populated & unique for *every* feature incl.
  disputed ones) — **never `ISO_A3`**, which is `-99` for France/Norway/many
  disputed entities. Display = `NAME` (short) / `NAME_LONG` (formal). **Source
  from full-attribute NE data (martynafford's GeoJSON or raw NE), not the
  attribute-stripped `world-atlas` TopoJSON** (which keeps only numeric id + `name`).
